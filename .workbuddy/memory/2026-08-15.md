  POST /jystock-app/api/v1/action/field 响应。该接口一次返回全部数据：

- 接口有动态 token 反爬（请求头 token+timestamp 由页面 JS 签名），直接 requests 调不通，必须借页面发请求。

## Bug 修复：response.body() 报 "Target closed"
- 用户反馈脚本偶发报"未捕获到 action/field 响应"。
- 原因：field 响应可能晚于 browser.close() 到达，在 response 回调里立即 response.body() 会报
  "Target page, context or browser has been closed"。
- 修复：回调只存响应对象，关浏览器前在 while 循环里（最长 30s，含重试点击 tab）等待并读取 resp.text()。
- 已实测通过（用户 cookie 仍有效），产出 result/jiuyan_action_2026-08-15.csv（73 条，实为 8-14 数据）。

## 新增：--login 一次性登录 + storage_state 自动复用
- 用户问能否自动获取浏览器 cookie。实测 browser_cookie3：Chrome 钥匙串加密读不到、
  Safari 需完全磁盘访问、Firefox 可读但未登录过 —— 直接读浏览器方案不可行。
- 改用 Playwright storage_state 方案：`--login` 弹窗手动登录一次 → 登录态存 jiuyan_state.json
  （工作区根目录）→ 之后无参数运行全自动（含 web-api 域的 SESSION）。
- 已用现有 cookie 生成 state 文件并端到端验证通过（73 条）。
- 保留 --session/--sl-session 手动模式和 --state 自定义路径。

## Bug 修复：--login 模式浏览器秒关
- 原因：页面未登录时也会发一次 action/field 请求（返回"登录失效"JSON，也含 "data" 键），
  旧逻辑"捕获到任何含 data 的响应就停"→ 立即判定未登录并关浏览器，用户没机会登录。
- 修复：_capture_field 增加 wait_login 参数，登录模式必须等到 errCode==0 且 data 非空的响应；
  每 2 秒轮询 + 重试点"全部异动解析"标签（登录后触发新请求）；登录模式不再删除登录弹窗。
- 回归测试无头模式通过（73 条）。注意：jiuyan_state.json 曾丢失一次（原因不明），已用现有 cookie 重建。
- 补丁引入 NameError（login_and_save 里 return data 但 data 未定义），已改为 return json.loads(raw)，回归通过。
- 按用户要求：--login 登录成功后浏览器不再自动关闭，数据先落盘，浏览器留给用户继续浏览，
  用户关闭窗口后脚本才退出（轮询 browser.is_connected() and context.pages）。
- 进一步要求：脚本存好数据即可退出，不必等用户关窗口。Playwright Python 无 detached 参数，
  改用 subprocess 自启 Chromium（--remote-debugging-port）+ connect_over_cdp，浏览器进程独立，
  脚本退出只断开 CDP、不杀进程，窗口保留。profile 存到 .jiuyan_browser_profile（可复用登录态）。
  沙箱里测可见窗口会被杀（GUI 限制），但语法/无头回归通过；用户从自己终端跑 --login 即可。
